# Lean Skill Authoring

Start with the repeated user task and identify the smallest reusable instruction, script, reference, or asset. Keep trigger metadata specific and the body concise. Search for an existing Skill before creating a new one.

Validate proportionately: check frontmatter and paths for every Skill; run a representative use case for a Skill with scripts, side effects, or consequential workflow rules. Do not require multi-agent pressure campaigns, five repetitions, test-first documentation cycles, or a commit for a normal local Skill.

For a behavior-changing workflow Skill, state its mode, stop condition, and whether it requires human acceptance. Do not make planning, full testing, review loops, scope expansion, or agent delegation unconditional defaults.
